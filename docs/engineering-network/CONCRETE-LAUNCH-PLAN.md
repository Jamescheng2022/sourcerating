# SourceRating Engineering Network｜“混凝土理论”开发与上线总纲 V1.0

**制定日期：2026-11-11**  
**范围：sourcerating.com 工程人脉平台改造**  
**实施基线：Engineering Network V4.2 原版信息流框架 + V4.5 文章编辑、私有草稿及 AI 审核试点**  
**状态：执行总纲；不代表生产上线授权。**

> 产品原则：先有骨架，再补真实内容，再建立可验证关系，再深化专业信息，最后通过可信身份与互动把它们结合成一个活的平台。施工中每一层达到可验收强度才进入下一层；严禁用演示数据、假认证、AI 伪造图片或虚假发布结果充数。

## 0. 严格保留、不再重复造的部分

1. **原 V4.2 首页**：今日头条式中央信息流；电脑端左导航 / 中信息 / 右关系与动态的三栏格局；手机端瀑布流与底部导航。
2. 已建项目发现、项目档案、企业档案、人物与作品、搜索、原发帖入口、八套 CSS/HTML 排版、六种专业文章结构。
3. 信息与媒体呈现可局部改善，但**不新造一套首页、不重写整个前端、不用静态概念图替代代码版本**。
4. Precast.World、NoGod、DESKGONE 与 SourceRating 在品牌、代码仓库、数据和运营任务上分别维护，避免交叉污染。
5. 生产 sourcerating.com **不得**因为试点构建通过就直接覆盖：必须另行执行 G4 上线闸门。

## 2. 混凝土五层：石子 → 沙子 → 粗骨料 → 细骨料 → 水泥

### 第一层：石子——骨架、基础设施与可靠性（P0）

**建设内容**
- 冻结原 V4.2 核心信息架构，逐页面按 390/768/1440 和真实触摸操作验收，统一桌面/手机导航与搜索行为。
- 完整源码、数据资源、package-lock、构建脚本、测试脚本进 Git 的独立分支；由 GitHub CI 原地检出构建，不再依赖会过期的 Vercel Sandbox URL。
- 正式站与预览站严格隔离；预览 noindex；独立部署、可回滚；不共享含服务密钥的客户端。
- 修复 P0：空内容发布、真实页面图片缺失、链接跳转错误、身份角色错配、发布行为不一致、平板宽度断裂、未知失败静默吞掉。
- 真实 Auth、RLS、来源数据读取、退出及会话过期；接口错误给出准确反馈。

**验收闸门 G0：** 从 Git **干净克隆**、npm ci、npm run build、JS/组件单测成功；没有密钥入库；每个主要页面实际浏览器点测；移动端无横向溢出；生产站无变化。

### 第二层：沙子——把真实项目内容填实（P0/P1）

**集中两个区域**（不同时铺满全世界）：
- **英国：先以 Midlands 地区为候选**，用已有 Contracts Finder 授标数据验证密度，然后缩小到一个项目/企业网络相对密集的城市群。
- **泰国：曼谷—春武里—罗勇产业走廊**，由可取得的公开项目与真实合作关系推进，优先验证项目和参与方。
- 具体城市边界必须由实测数据覆盖与可接触企业密度决定，不能先写死然后硬填。

**项目记录最低字段**：名称、工程类别、地理范围、买方/业主（存在证据时）、公开状态、原始发布日期、来源 URL、抓取日期、对应证据、更新时间、语言、声明/纠错入口。

**三个数据可信度等级**
- A：公开来源记录，显示原始来源和时间；**并不**证明现场进度或人员参与。
- B：多来源交叉证实，标记已交叉核验字段；冲突保留待核查。
- C：经授权参与方认领并提供证据，通过人工复核；具体事实和照片逐条标记。

**过滤规则**：旧纪录、世界银行融资条目、采购公告、真实在建工程分别标注；低信任或无价值页面可以显示在检索库，但不批量开放搜索索引。

**试点目标（验收指标，不是现有事实）**：每一区域至少 50 个经过抽样复核且可打开原文的项目档案；全球总量本身不是 KPI。抽样核查项目名称、国家、状态、来源与关系证据；关键事实错误率目标低于 2%，原文断链目标 0。

### 第三层：粗骨料——项目 × 企业 × 人的关系网络（P0/P1）

- 建立事实关系边：Project—Owner / Designer / Main Contractor / Subcontractor / Supplier / Engineer。
- 每条边必须有：关系角色、原始证据、证据时间、验证状态、创建者及撤回/纠错通道。
- 单纯文本提及、相似公司名、AI 推断不能自动升格为真实参建关系；同名企业先去重、核对法律实体。
- 企业认领：邮箱域名、授权证明或项目资料多因素复核；认领不自动赋予编辑其他企业/项目的权限。
- 工程师个人档案：只在本人授权后公开；作品/经历需能关联并允许本人纠错与撤销；人员空档宁可显示 0，也不造假。
- 形成可点击的闭环：信息流 → 项目 → 参与企业 → 人员/作品 → 相关项目。搜索覆盖所有真实实体。

**试点目标**：每一区域 25 家可核对企业、10 条具有证据的参建边；首批真实工程师由用户邀请核验，绝不将数据库人物提及统计成“注册工程师”。

### 第四层：细骨料——专业深度、现场影像和高质量文章（P1）

- 现有 **52 套工程类别视觉模板**作为缺图兜底：显著标注 *AI-assisted generic illustration; not this project’s site photo*；不能暗示项目形态、现场完成进度、设备型号或工程质量。
- 对拥有使用授权的**真实项目照片优先显示**，并保存作者、授权、来源、拍摄/提交时间、说明、替换与删除记录。禁止未授权转载现场图片。
- 采用既有 **6 种文章结构 + 8 种轻 HTML/CSS 排版**，不再大规模重做前端。
- 作者只上传照片并讲几句话；系统先提出 **少量、可点选/可补充**的有针对性问题，再整理背景、条件、方法、证据、结论、反思。
- AI 必须克制：不增造参数、标准号、地名、人员身份、签证许可、测试结果；有证据缺口则提示“待核实”，不自动修正工程参数。
- 审稿分两层：本地确定性检查（单位、逻辑、日期）＋授权的服务端模型语义意见（明确“AI 建议，非独立核验”）。
- 图片/文件存储需私有桶 + RLS/存储策略 + 类型/大小限制 + EXIF 清理 + 删除权；失败不可假装上传成功。
- 文章模板输出为**可编辑正文/HTML**，不是只输出一张静态漂亮图片。
- 专业知识内容优先作者一手经验、现场数据与关键决策，不做批量 AI 空洞水文。

**验收标准**：一个真实工程师 10 分钟内完成“素材→追问→草稿→逻辑审核→确认”；编辑回填、移动端、照片授权标注通过；事实更正与撤稿可操作。

### 第五层：水泥——可信账户、互动、冷启动和留存（P0/P1）

- Auth：邮箱验证/登录先贯通，再评估 Google 一键登录；用户名/角色与授权关系不能仅靠客户端声明；跨账号 RLS 权限测试必须通过。
- 用户可以认领、纠错、保存关注、投稿；管理员审查冒名认领、虚假工程、盗图、骚扰与垃圾内容。
- 社区：先做项目订阅、专业内容收藏、低成本联系；群聊/AI 总结/收费协作室为后续深度功能，不阻塞首发。
- 主动冷启动邮箱使用 **connect@sourcerating.com** 作为统一品牌身份，**发件前必须验证**收发、SPF/DKIM/DMARC、退订、抑制名单、发送频率和地域法律合规。
- 邮件只面向**能提供确切项目/企业依据的相关企业**，邀请核对项目档案/认领资料；不自动将不相关联系人大批量发外贸产品推销邮件。
- 英国 B2B 邮件遵守 ICO 关于 corporate subscribers、个人数据的 UK GDPR 法律依据和退出权的说明；泰国个人资料按适用 PDPA 要求设计，需法律核实。首轮外联由 Owner 批准名单和样稿后启动。
- 每封邀请指向**对方具体项目/企业页面**及清晰认领/纠错入口；不能邀请其认领不存在或未验证的项目。
- 留存闭环：有价值的行业内容 → 有证据的关系 → 认领贡献 → 内容发布 → 他人互动 → 质量提升 → 自然回访。

**冷启动目标（不是已实现）**：首批 20 家/20 人经人工筛选邀请；追踪送达、有效回复、认领完成、7 日回访。只要投递/资料质量低就暂停发送，不追求群发数量。

## 3. 必须分开验收的发布级别

| 闸门 | 面向用户的版本 | 必须通过的条件 | 未通过如何处置 |
|---|---|---|---|
| G0 源码基线 | Git 可重建预览 | 完整代码、干净构建、回归检测、零密钥 | HOLD，不能依赖临时 URL |
| G1 数据展示 | 内部/只读公开预览 | 原版 UI、50+ 项目/区域来源、来源可点、图片说明、noindex | 不对外营销 |
| G2 搜索可见的内容公测 | 受控公开网页 | 高质量页面有原生可抓取 URL、非 Hash 主地址、SSR/SSG 或等效可验证渲染、canonical/robots/sitemap/Article 或适用结构化数据、索引抽测 | 不提交全站 sitemap / 不移除 noindex |
| G3 邀请制协作 | 真实注册/认领/创作 | 注册邮件回跳、两账号隔离、跨设备草稿恢复、图片存储、模型实际成功回执、审核/撤稿、内容发布链路 | 仅保留只读 |
| G4 主域切换 | sourcerating.com 正式新版 | 原有 URL 迁移映射 + 301、GSC/GA4、生产数据备份、人工业务验收、回滚演练、SSL/DNS、监控 | 主站保持现状 |
| G5 扩区与商业化 | 付费项目协作/采购代理 | 区域内真实用户活跃、受访/认领正反馈、付费价值被验证 | 不提前堆收费功能 |

**SEO / GEO 的底线**：索引公开、可信、可验证的原创项目/企业/人物/文章页面；不要用自动生产的低价值条目铺满索引。Google 官方说明 AI 搜索曝光沿用搜索基础优化，无“特殊 GEO 标记”能保证被引用。详情参考文末官方文件。

## 4. P0、P1 顺序和不做的事

**P0（先完成）**
1. Git 完整源码 + CI + 生产/预览隔离 + 可回滚。
2. 三屏交互、项目卡片/详情/搜索与正确的真实来源。
3. 账户注册、邮箱认证、真实会话与跨账号隐私；云端草稿持久化及跨设备测试。
4. 模型审核真实调用/失败关闭/用户许可/费用上限；图片存储真实权限。
5. 管理员审核、纠错/撤稿、内容发布流水线。
6. 搜索索引 URL 迁移及旧站文章保留策略。

**P1（P0 不阻塞的逐步加深）**
1. 两个小区域的项目信息深度、参建关系与主体验证。
2. 企业/人员认领、相似实体去重、技术案例与多语言质量。
3. 有归属的消息/关注/收藏、反馈与运营监控。
4. 精准邀请 connect@sourcerating.com；首轮必须小样本验证。
5. 小范围收费意向测试，暂不以收费功能阻碍真实内容和用户留存。

**本轮明确不做**：重新设计首页；大规模自动群发；把模拟人员填入线上；自动编造工程现场；在没有实际发文、登录、索引测试的情况下宣布“已上线”。

## 5. 交付周期（规划假设，不是承诺）

**假设**：原版前端维持不变；一名执行代理负责云端源码/数据/部署，Claude/Codex 可独立审查，Owner 负责真实来源确认、首批用户与主域上线批准。时间会受第三方额度、鉴权和关键缺陷影响。

| 时间窗 | 输出 | 退出标准 |
|---|---|---|
| 第 0–2 天 | Git 备份与 CI，锁定 P0 清单，回滚预案 | G0 |
| 第 3–7 天 | 原 UI P0 修复 + 来源分类 + 登录/草稿权限测试 | G1 内测 |
| 第 2–3 周 | 第一个区域 50 个精选真实档案 + 真实可索引页面技术改造 | G2 小范围内容公测 |
| 第 3–6 周 | 第二地区数据 + 企业认领 + 真实投稿与媒体云存储 | G3 邀请制 |
| 第 6–10 周 | 小规模外联验证 + 全面回归 + SEO 旧 URL 迁移 + 回滚演练 | G4 条件性正式上线 |
| 上线后 4–8 周 | 观察留存、数据纠错、内容供需互动；再考虑功能和收费 | G5 数据决策 |

**速度原则**：能上线的不是页面数量，而是一条最小完整闭环；可先上线只读高质量资料，但不可把未验证的“真实用户系统”当成上线版本。

## 7. 每周只看能说明价值的指标

**主指标**：当周真实、经过验证的“项目—企业—人员有效连接”新增数；空注册和假活跃不算。

**辅助指标**：项目来源可验证率、关键资料错误率、资料纠错闭环时间、企业认领完成数、采访完成率、真实文章被同行收藏/引用/回访、有效邮件回复率、7 日有效回访、GSC 真实曝光/点击、重大故障数。  
**约束**：隐私越权 0 容忍；伪造项目照片 0；虚假已验证标识 0；生产无授权发布 0。
