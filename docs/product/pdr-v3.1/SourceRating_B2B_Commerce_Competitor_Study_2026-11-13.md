# SourceRating｜AI-native B2B Commerce 竞争格局与战略判断

**研究日期：** 2026-11-13  
**性质：** Master PDR v3.0 竞品附录 / 商业战略研究，不代表产品已部署  
**研究范围：** 国际 B2B 电商、AI 寻源、制造业 RFQ、采购 SaaS、供应商协作、工程证据平台、Agent-to-Agent 商务协议  
**方法：** 优先企业官方产品文档、公告与上市公司披露；辅以 McKinsey、Deloitte、专业采购技术评估和 Reddit 讨论。除特别说明，没有进行付费账号功能实测、客户访谈或产品安全审计。竞品能力均以公开可核实资料为准。

---

## A. 结论摘要

**判断：方向有商业价值，但不是一个空白市场。** “AI + B2B + 项目协作 + 业务记忆 + Agent”正在成为行业主流技术路线。SAP 在 2026-11-03 明确提出 Business Network 成为企业间商务的 intelligence and execution layer；Omnea 2026-09 发布采购 aOS；CADDi 2026-08 重构为制造业数据、语义、Agent、执行四层平台；Jiga 已支持 CAD 文件关联讨论、RFQ、供应商直接消息、版次及 ERP。新平台 Buyer24 甚至公开支持邮件发起 RFQ、WhatsApp、报价抽取与历史版本。这些均与 SourceRating 长期设想产生实质重合。

**机会不在“功能尚不存在”，而在“用户仍难以低成本、低门槛地完成跨企业复杂采购”。** 初期首选中国供应商与海外买方已有联系、但订单需要图纸/BOM/技术澄清/多轮报价/工程或质量签核的交易场景。产品不需要取代 Alibaba、WhatsApp、SAP、Zoom、CAD；需要成为贯穿这些工具的授权、过程证据、变更和项目记忆层，并提供顺滑的原生协作 Room。

**建议定位：** AI-native B2B Collaboration & Commerce Infrastructure / 复杂 B2B 交易的协作与执行基础设施。面向用户的首期说法宜具体：**Turn conversations, specifications and supplier quotes into decisions you can trust.** 不要一开始宣称“取代所有电商、SaaS”。

**最迫切的差异化测试：** 买方主动创建房间、供应商无需强制注册就能回复 RFQ、每个报价行绑定不变的需求版本、所有沟通保留原始出处、AI 按授权提示而不擅自确认、现有邮箱和 ERP 可衔接。测试用户是否愿意把第二个真实采购项目继续放进平台。

## B. B2B 电商正在发生的结构变化

| 旧范式 | 新范式 | 商业影响 |
|---|---|---|
| 商品目录、供应商搜索 | 意图理解、Agent 寻源 | 仅靠目录和关键词 SEO 的流量壁垒可能降低 |
| 发送 RFQ 等待邮件 | AI 辅助询价、自动追单、跨渠道回复 | 平台的价值转向采购时间和成交效率 |
| 平台留言与邮件附件分离 | 消息、RFQ、文件、版本、报价行关联 | 过程证据成为可复用资产 |
| 采购员手工维护表格 | 非结构化资料抽取 + 人工确认 | 避免把 AI 输出直接当正式记录 |
| 独立软件各自记录 | SaaS/API/MCP/A2A 互联 | 客户保留原来的 ERP/CRM/OA 系统 |
| 公司负责全部交易操作 | 企业授权的 Buyer Agent / Supplier Agent | 控制权、审核、身份和来源证明变得重要 |

**市场侧证据：** McKinsey 2026 B2B Pulse（接近4,000名、13国决策者）称买方平均使用约10个渠道；71%的受访 B2B 企业提供电商，其中数字渠道约贡献电商企业三分之一收入。Fictiv/MISUMI 的2026年300多位行业负责人调查中，81%表示供应商寻源与管理日益耗时昂贵。这些数据调查口径不同，不能合并计算市场总规模。

**市场规模不能用总 B2B GMV 作为可捕获 SaaS 收入。** 如 SAP 提及其 Business Network 在截至2026年Q3的12个月内承载逾8万亿美元商业流量，属于网络处理/促成交易额，并不意味着采购软件营收或可被新平台获得的市场规模。

## D. 最关键竞品的产品拆解

### D1. Jiga — 工业定制采购协作正面竞品
- RFQ/订单、零件与版本、消息、DFM 评论、CAD 文件、ERP 对接。
- 允许买方保留现有供应商关系；供应商直接参与，无须强制转用新采购流程。
- 公开叙述“AI monitors. Experts judge”与我们提出的“AI 静默整理、人工最终确认”高度相似。
- Jiga 公开价格为免费注册、按采购零件付费（需以每笔实际合同复核）。
- 研究结论：SourceRating 不能再以“消息与报价关联”作为单独差异化，而应验证跨行业中立、双方各自拥有数据资产、历史复用、跨语言和外部系统关联的组合是否优于其方案。

### D2. CADDi — 企业隐性知识变成数据资产
- 2026年8月发布重新构建后的制造业平台；Data Layer → Semantic Layer → Explorer/Agent → Workflow Products。
- CADDi Quote 集中 RFQ、供应商报价比较、授标理由，并沉淀未来可复用的采购判断。
- 已从早期直接参与制造的模式转向软件平台；2024年停止自营制造。
- 研究结论：SourceRating 的“项目记忆 / 企业记忆”是有明确竞品的成熟战略方向，不能只靠 AI 摘要取胜；要重视跨组织授权下、原始证据链接到正式决策的完整性，以及客户长期使用的复利。

### D3. Omnea & Zip — 采购 OS / AI 治理与 SaaS 集成
- Omnea 于2026-09-28推出 Agentic Operating System：Context Engine、Agent Library、Governance。
- Zip 于2026-06推出 Superagents、采购 MCP 等；支持与现有 ERP/P2P 系统协同、审批与审计。
- 研究结论：“Integration Hub”“Agent Router”“企业上下文”不是空白，应避免从大企业复杂内部采购全面对抗它们。SourceRating 首选外部采购双方共享工作区，既服务 Buyer 又服务 Supplier，支持客户带自己的现成供应商。

### D4. SourceDay — 供应商参与门槛的答案
- 邮件直接确认和更改 PO，供应商不登录也能参与；可选择完整 Dashboard 或批量上传。
- PO 行级成本、数量、交期更改有建议/反建议/买方审核/ERP 更新闭环。
- 研究结论：SourceRating 的 Project Room 必须保留，但供应商不能被强制先注册并学会聊天才能报价。应支持邮件原生操作，同时保持所有结果写入带来源的 Room 事件和 RFQ 状态。

### D5. Buyer24 / Mandel / Cavela / IQmatica — 新锐竞争者
- Buyer24：用户邮件转发 RFQ，AI 生成正式询价、自动追供应商、接收邮件和 WhatsApp、提取报价行、比较报价且保留版本。
- Mandel：在现有邮箱/ERP 中追踪供应商、订单变化，避免逼供应商去新系统。
- Cavela：AI 搜索和联系工厂，通过常见渠道取得报价。
- IQmatica：买方 Agent 找到供应商 Agent，利用已批准的价格/权限规则返回机器可读商务答复，例外才人工审批。
- 研究结论：SourceRating 第一阶段必须实测比“邮件+自动 RFQ 平台”多出来的真实价值：多人文件审查、专业对象绑定、跨组织权限及过程记忆。这些才是潜在区分点。

### D6. SAP、阿里巴巴和 Amazon — 庞大生态约束
- SAP：网络、业务流程和大型客户关系极深。2026-11-03明确提出 B2B Network 的智能执行层。
- Alibaba.com：截至2026-03-31据其20-F披露，有超过24万付费商户、逾4,700万年度相关采购用户；Accio Work已宣称5万付费用户（2026年8月电话会）。
- Made-in-China于2026-10发布SourcingAI 3.0，强调寻源匹配、谈判与贸易服务。
- Amazon Business于2026-10增加对话式审批、订单和采购分析。
- 研究结论：不能尝试在广泛商品目录、广告流量、标准化办公用品上与大平台正面交战。应成为它们之外、买方与既有供应商之间的中立协作和业务证据层。

### D7. Aconex / CoLab / Procore — 不应忽略的专业功能基准
- Oracle Aconex 已有文档不可变审计轨迹、版本、邮件/往来历史和责任记录。
- CoLab 已能比较CAD修订、2D/3D图纸、携带之前版本的批注意见；2026更新了AI能力。
- Procore已提供合同审查、RFI、Submittal及招标比较AI Agents。
- 研究结论：工程证据和审查已经成熟；SourceRating应提供通用对象模型与授权连接器，避免自己重造专业 CAD、文档审查套件。

## E. 有依据的市场需求与采纳障碍

### E1. 用户并不缺平台，缺的是“不增加额外步骤”
- McKinsey 2026 调查：B2B买家平均跨约10个渠道；统一体验是基础而非增值功能。
- Reddit 2026年供应商入驻及采购讨论多次出现“Email + Excel”“新供应商门户难推动”，部分讨论特别提出：邮件中没有固定格式的报价依然普遍。匿名社区反馈不构成代表性样本，但值得转化为真实用户测试问题。
- SourceDay、Buyer24 的免登录邮件路径不是偶然；这是竞争者对供应商行为的明确产品回应。

### E2. 买方和供应商谁付费？
- 供应商通常不会为了给一个潜在客户报价而主动订阅新的采购工具。
- Buyer/总包采购方如果能够量化减少重复澄清、漏项和变更争议，拥有更可验证的付款动机。
- 供应商可能为多个买方重复复用的 Sales Workspace / Quote Memory 支付，但须先观察是否产生独立使用行为。
- 早期应避免每笔交易收不透明佣金，因为平台主张中立、报价隔离与买方利益可能发生冲突。

### E3. 用户愿不愿意转用聊天室？
应采用“**Room 是正式协作中枢，但渠道不强迫迁移**”原则：
- 买方愿意的情况下，在 Room 处理完整技术讨论与文件。
- 供应商通过专属链接或邮件直接响应，完成需求和报价录入。
- 有持续合作、跨角色和文件审查需求时，供应商可从轻量入口无缝升级到完整 Room。
- 外部导入资料明确标记“imported”，原始邮箱/WhatsApp/微信授权来源与证据等级不能假装成平台原生记录。

## F. SourceRating 可争取的真实差异化

### F1. 不是“AI 做得更聪明”，而是“AI 不会破坏商务记录”
每个对象有版本和可追溯状态：Message、Requirement、Drawing、RFQ、QuoteItem、Approval、PO、Change、Evidence。正式状态只有授权人能确认，AI只生成候选。

### F2. 对象级关联是核心，不能停留在文件级附件
消息可以指向一条BOM、一个设计构件、文件页码、报价行、合同条款。相关设计变更触发**确定性**依赖检查；AI负责解释与发现关联疑点，但不独自决定价格和工程批准。

### F3. 双边共享流程 + 各方独立数据
买方和供应商在共享 Room 协作，双方都可长期使用自身 Organization Memory。Supplier A 与 Supplier B 隔离；买方内部审批独立；代理贡献有审计。所有跨组织关系由授权定义。

### F4. Integration-first 但不做插件超市
- 视频：Zoom/Teams。
- 文档：PDF.js、成熟Office协作服务。
- 工程：Autodesk/Speckle/CoLab等专业查看/评审服务。
- 企业软件：CRM/ERP/OA/PLM。
- AI工具：模型Provider、MCP，后续可A2A。
Core自己掌握的是权限、事件、业务对象、决定、证据、检索上下文和长期记忆。

### F5. 面向 Agent 的数据层
未来 Buyer Agent 与 Supplier Agent 需要的是经过权限过滤的产品能力、有效报价、承诺状态和原始证据。平台应该预留机器可读的 RFI/RFQ/Quote/Approval API，而不是赌某个 AI 模型或某套专有协议赢得全部市场。

## G. 产品定位选择与排序

| 路线 | 优势 | 主要风险 | 建议 |
|---|---|---|---|
| 通用全球B2B平台（从第一天就是阿里巴巴竞品） | 最大叙事 | 双边冷启动、目录、流量与信任成本巨大 | 不建议首期 |
| 采购 Agent SaaS（对标 Zip/Omnea） | 可收企业订阅 | 同质化强、客户内部系统复杂、销售周期长 | 后续扩展 |
| 工业件撮合市场（对标 Jiga/Xometry） | 行业聚焦、价值明确 | 供应链质量与履约责任重 | 适合作为试点，不宜过早自营全部交易 |
| **跨企业复杂采购协作基础设施** | 保留已知合作关系、沉淀双方过程数据、兼容各渠道 | 必须真正比邮件更省事 | **最推荐** |
| 纯聊天+AI助手 | 快速上线 | 很容易被Chat/办公套件复制 | 不建议单独定位 |

**建议站点定位：** SourceRating — Where complex B2B deals get done.  
**解释性副标题：** One workspace for buyers and suppliers to discuss specifications, review files, compare quotes, approve changes and remember every decision.

**不要用“供应商打分”作为唯一首页功能。** SourceRating 品牌可以保留，但产品说明必须明确“协作与成交过程”而不是仅“供应商点评”。

## H. 首次真实产品的最短完整闭环

### 核心旅程（不是削减聊天）
1. 买方创建Project Room，上传图纸、BOM、RFQ。  
2. 买方邀请已有供应商；每家供应商有独立访问范围。  
3. 供应商无需复杂入驻即可通过受控链接/邮件回复，亦可进入完整 Room。  
4. 实时聊天、附件、PDF查看和基础批注已可用。  
5. 每条关键消息/文件旁有 Ask AI；翻译可按用户偏好展示原文。  
6. 异步 AI 生成候选事项，Needs You由有权限的人确认。  
7. 供应商报价逐行绑定不可变RFQ/BOM版本；设计变更触发需要复核的行。  
8. 买方比较报价、做决定，形成时间线和证据导出。  
9. 可选择同步到客户已有CRM/ERP/OA；最初仅提供审计型Adapter契约。  
10. 第二次采购可复用供应商、资料、报价历史和项目记忆。

### 首期禁止的误导
- 未做真实外部授权，不显示“已导入微信所有聊天”。
- 项目结论没有人工确认，不显示“Approved”。
- 仅有演示报价，不显示“真实供应商报价”。
- 没有跨组织权限测试，不能宣称“企业安全”。
- 没有可恢复的生产部署，不能宣称“正式上线”。

## I. 商业模型与付费测试（假设，不是已验证定价）

| 用户 | 免费/试用入门 | 潜在付费触发 |
|---|---|---|
| Buyer | 第一个真实项目、基础Room和文件交流 | 多个项目、证据包、跨角色审批、组织记忆、集成 |
| Supplier | 接受RFQ、查看指定文件、回复、报价 | 私有产品知识库、历史报价、跨客户管理、销售AI |
| Agent / Intermediary | 作为被邀请参与方 | 线索记录、代理工作流、白标报价、客户管理 |
| Enterprise | 受控试点 | SSO、数据区域、扩展保留/审计、高级连接器、治理 |

在访谈前不锁定金额。测试三种收费假设：组织订阅、按活跃采购项目计费、AI/证据高级功能额度。不建议一开始按交易金额抽佣。

## J. 推荐验证实验：90天

### 样本结构（建议目标，而非现有承诺）
- 找3–5家真实买方或采购代理组织。
- 10–15家真实供应商，覆盖至少两个独立行业子类。
- 选取至少6个真实且允许使用平台的RFQ/项目，其中至少2个有真实修订图纸/BOM。
- 收集之前的邮件/Excel流程作为基准；不得在未经授权的情况下读取外部私人聊天。

### 分段闸门
- **D0–30：**SourceRating真实消息、邀请、文件、权限、AI候选/人工批准闭环；连接器接口和报价行数据定义。
- **D31–60：**在相同Room上完成真实供应商逐行报价、修改版本与回溯；外部邮件回复走官方、授权通路；WePrefab作为行业对象来源的可选测试。
- **D61–90：**观察供应商二次使用、买方第二个项目、减少的邮件或人工整理时间；试验组织付费意愿。

### 证伪阈值（事先设定，可按基线校准）
- 零跨组织数据越权；消息和原始报价不丢失。
- 完成 >=6 个真实 RFQ，不以示例数据计数。
- 不培训的供应商能从邀请完成至少一次文件阅读、回复或报价。
- 买方至少有2个组织自发启动第二个项目（若样本3–5家，目标仅供测试）。
- 至少1–2家组织表达明确的付费意向或接受实际小额收费试验。
- AI 输出应支持原始来源回溯，错误不自动写正式状态。

若连续测试发现供应商更偏好邮件、买方仍愿意为了协作记录付费，应优化“邮件原生 + Room记录”；不必强制迁移全部聊天。若买方完全不愿使用也不愿付费，则应重新评估核心定位。

## K. 给 Master PDR v3.0 的修订建议

1. **战略定位：**从广义 Collaboration OS 调整为 **Complex B2B Commerce Collaboration Infrastructure**，强调业务成交、履约和过程记忆。
2. **明确竞争事实：**聊天关联报价、AI整理、邮件免登录与供应商能力均已有实质竞品，不得宣称首创。
3. **统一入口：**Room核心不变，但Email、可撤销受控链接、必要时WhatsApp官方通道构成平等的工作入口；目标是最终证据完整，不是把每条消息都迁移到平台UI。
4. **强制结构化对象：**RFQ Revision、BOM Snapshot、Quote Line、Change Impact、Approval、Source Event ID是核心模型，而非后续可选插件。
5. **独立买卖双方的真值：**Buyer Internal、Supplier Private、Shared Room、External SaaS System of Record 各有独立权限与数据所有权。
6. **AI前置授权：**Agent动作必须根据业务权限、风险和显式授权执行，记录审计；模型选择可替换。
7. **供应商价格与利益透明：**中立协作SaaS与平台代理服务业务分离并披露。
8. **Agent-ready而非Agent-only：**预留MCP/A2A/Commerce Adapter接口，但不要首期押注尚在演进中的UCP/AP2等协议；当前UCP更偏零售消费交易。
9. **最小可用完整骨架：**Identity + Room + File + Ask AI + Translation + Quote + Human Commit + Evidence + Connector Contract全部在首期架构中；每个模块有真实可验收的基本纵向能力，后续细化。
